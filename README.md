# Media Organizer · 本地多媒体资料库

本项目的核心是 **本地照片和电影的管理、预览与去重**，让你打开磁盘目录后，就能浏览内容、找到重复文件，并在文件旁直接处理。

- **管理**：按文件夹浏览照片和电影，搜索、打开原文件、定位所在目录；需要归类时，先预览再复制整理。
- **预览**：照片缩略图、放大、连续浏览和并排对比；电影封面、影片详情和默认播放器播放。标签、用户名、分类计划等放在辅助入口，不作为浏览或删除的前置步骤。
- **去重**：照片和视频用完整 SHA-256 确认内容完全重复；相似照片单独展示并排核对。文件旁的“删除…”直接进入确认，精确重复至少保留一份。

macOS 与 Windows 共用一套界面和业务代码。**扫描只读；复制整理和移到废纸篓 / 回收站均须预览并再次确认。尚无原媒体改名、分类移动、永久删除或联网上传功能。**所有可修改源码、启动文件和说明都集中在此项目目录。

## 媒体中心：浏览管理优先

macOS 和 Windows 10/11 共用固定左侧导航，首页、电影、视频、照片、相册与合集、收藏、资源管理、标签与分类、媒体库、整理工具和设置。扫描完成后默认进入首页，主内容随导航切换；常用去重从侧栏“重复与相似”直达，原有高级查重与复制整理保留在“整理工具”。

- **统一卡片与详情**：点击电影海报进入封面、简介、年份、演员、类型、评分、标签和文件详情，再选择播放；普通视频为缩略图网格；照片为瀑布流与大图，可用上一张/下一张或左右键连续查看。详情关闭后保留列表位置。在同一媒体详情中保存收藏、标签、评分或备注，会保留视频预览与尚未提交的输入，并显示保存结果；关闭详情或切换文件时停止预览。视频详情提供“页内预览”，按需读取本次扫描中身份核对通过的视频，支持分段读取和拖动播放位置；仍可选择“播放”交给系统默认播放器。MP4/M4V/MOV/WebM 能否页内播放取决于浏览器或系统 WebView 的编码支持，其他容器使用系统播放器；不自动转码，尚不保存播放进度。
- **补充视频封面**：无封面的照片卡片提供“补预览”，视频/电影卡片提供“补封面”，使用已安装的共用 FFmpeg 或 Mac 原生降级组件读取照片缩略图或单独截帧；只在本地报告写预览图，不改原视频。生成超时或格式不支持会说明原因，可重试或用系统播放器查看，不承诺所有编码都有封面。照片墙、视频墙、详情及重复/相似列表中，启用了相应解析时，进入可见范围的缺图会自动排队生成；关闭照片/视频解析时不自动补图，仍可主动点击按钮仅生成所选文件的预览；页面显示本次预览队列的数量与百分比，失败可逐项点“补预览”/“补封面”重试，不会反复自动重试损坏文件。自动补图与手动重试共用队列，翻页离开后尚未开始的旧卡片不再解码；详情内补图原位更新，保留正在播放的视频和未保存的标签。损坏预览会显示重试入口，修复图在刷新和重启后优先使用；生成的缓存图丢失或损坏可再次补图，仅替换本地报告中的生成图片。身份和组件未变化时可由下次扫描复用，包括超过首次照片预览额度的已补图片。缓存封面不再占用本次新截帧数量额度，避免后面的文件一直轮不到生成。
- **视频信息与筛选**：Mac / Windows 共用 FFmpeg 读取每个视频文件的时长与编码尺寸，已有本地封面的影片也会读取，不受封面数量上限影响。单文件卡片直接显示，多版本或分段在详情逐文件展示，不相加为电影总时长。可按不足10分钟、10分钟至不足1小时、1小时及以上或时长未知筛选；尺寸按编码画面短边划分，不按文件名猜画质。组合条件须由同一视频文件满足，匹配后仍保留整部电影或整个重复组。未知信息不会被当成0秒，也不会把照片列入未知视频；旧报告需重新扫描补充。 未生成封面的卡片显示扫描未启用、生成失败或尚未生成等状态；启用“读取视频时长、尺寸与封面”后重扫。部分编码、读取失败或封面数量上限仍可能没有封面，不表示文件一定损坏。
- **首页与最近记录**：显示电影、视频、照片、收藏数量、最近更新和目录相册；成功打开后保存“最近打开”。最近更新按扫描记录的文件修改时间排序，不冒充实际入库时间或继续播放进度。
- **搜索**：Mac / Windows 均默认搜索当前页面，照片、电影、收藏、当前目录/相册/合集及标签范围不会因输入搜索词而丢失。可将“搜索范围”切换为“全部媒体”，跨媒体类型检索名称、完整路径、标签、本地电影演员/简介与已有照片元数据；显式类型、年份和类型标签筛选仍生效。搜索卡片显示末尾目录与文件名，悬停可查看作品内的完整文件路径，以区分同名资源。全库结果提供返回原页面按钮，清除搜索也回到原范围，不修改媒体或合集记录。电影资料来自已有本地 NFO，不联网刮削。
- **原文件夹浏览**：两平台的“资源管理”按扫描来源逐层进入目录，用路径导航返回上级；默认只显示本层媒体，可勾选“包含子文件夹”。目录卡片和目录相册显示完整路径，区分不同磁盘、网络共享与同名目录；只展示扫描快照中的媒体目录，不即时读取磁盘，也不移动原文件。文件夹和媒体分别每页50项，切换范围或筛选会清空勾选，刷新保留仍存在的浏览位置。
- **筛选与排序**：在“筛选与排序”中按已有影片年份/照片记录日期、影片类型标签筛选，按名称自然排序、最近/最早修改时间或文件大小排序。未知日期不推断年份；重置筛选保留所在目录。当前目录搜索保留“包含子文件夹”开关；搜索或切换范围从第一页开始并清空旧勾选，全库搜索只临时忽略原目录/合集/标签范围。
- **目录人物标签**：在“资源管理”进入人物文件夹，点击“以‘目录名’作为目录标签”，该目录及子目录中的照片、视频和电影会集中到同一标签。后续新增文件在重新扫描后自动继承；可从目录取消绑定。绑定按完整路径区分不同磁盘和同名目录；同名标签会汇集浏览。只写资料库记录，不修改文件夹，不分析人脸、不自动识别人。演员信息仍来自已有本地 NFO。
- **照片按月份浏览**：在照片页将“照片墙”切换为“按月份查看”，按扫描保存的年月倒序分组，点击仍可大图连续浏览。日期优先来自 EXIF，也可能来自文件名或修改时间，推测来源会提示；未知日期单独显示。每页50项，同一月份可能跨页。
- **收藏与标签**：照片、普通视频与电影统一收藏，并可在详情中保存本地标签。电影原有评分与观看备注继续使用原存储。旧电影“收藏”标签会作为初始收藏状态，媒体中心中可独立覆盖；标签页按标签集中查看媒体。
- **相册与合集**：扫描来源中的原目录自动形成目录相册；可创建、重命名、删除自定义合集，在整理模式把照片、视频、电影加入或移出同一合集。这里的增删只修改资料库记录，不创建、搬动或删除媒体文件。单页50项，超过单次200项选择时分批管理。
- **主动整理模式**：普通浏览隐藏勾选与删除；打开“整理模式”后显示批量选择、加入合集、移出合集及回收站清理。电影作品展开其视频文件，最多200个文件预览；依旧走原有身份检查、SHA-256重复保留、预览确认、回收站、锁和日志，不会直接执行删除。
- **重复与相似直达**：Mac / Windows 均可在媒体中心内切换精确重复与相似照片，按组展示小图、路径、对比、勾选和删除；每页10组。两个页签均支持跨页勾选，再点击“删除所选…”，一次确认最多200个文件。精确重复可点击“保留这份，勾选其余”快速选择副本，也可跨组选择；确认时列出保留路径和待清理文件，不能选中整组全部副本。完整SHA-256校验与保留文件身份检查继续生效，相似候选没有此快捷清理入口，也不自动视为重复；未启用检测或达到候选上限时明确提示。清理仍先预览并确认，精确重复至少留一份。
- **确认不相似**：相似照片每对候选可点击“确认不相似”，立即从待核对列表隐藏，跨刷新、重启和同一文件身份的重扫保留；可从“已确认不相似”恢复。任一原文件身份变化后会重新进入候选。只保存核对记录，不删除文件，也不影响精确重复。
- **在重复分组内查找**：默认在当前精确重复/相似照片页搜索名称、路径及所属媒体的资料、标签和备注；任一文件同时满足搜索与筛选条件时显示完整一组，不隐藏其他待对比副本，也不改变清理范围。分组排序按首个文件名、组内最大文件大小、最近/最早文件修改时间；全库搜索返回后保留精确/相似页签。
- **卡片快捷操作与返回**：照片/电影/视频可直接收藏，单文件电影/视频可快速播放；整理模式可在卡片直接删除，并选择两张照片并排对比。删除只显示一个确认框，列出文件、取消和“确认删除”，不再嵌入“操作进度与记录”页面，也无需额外勾选确认。执行时原框显示简短状态和安全停止按钮，后台操作记录继续保存以供异常核对。取消后直接返回原列表；本页面提交的删除任务全部成功后也自动返回，失败或中断保留明细。对比中点击删除会先关闭对比，再显示同一个清理确认框，避免弹窗叠加；取消或完成后返回列表。返回后保留目录、筛选、页码和可用滚动位置，并按本次报告全部有效操作记录隐藏已清理成功的文件；这不是重新扫描或即时磁盘检查，外部恢复后需重扫。任务进行中会自动更新状态，记录异常或刷新失败时暂停清理。
- **媒体库与设置**：从侧栏“媒体库”添加目录和查看扫描进度；“设置”管理目录变化自动更新、定时扫描与备份恢复。跨扫描索引保留断开磁盘的历史记录。当前媒体墙对应所选扫描快照，文件变化后需重扫。

电影与普通视频按本地资料、目录及命名线索区分，分类可能需要人工核对，不分析内容推断影片。没有识别线索时留在“视频”；在视频详情可点“标为电影”，手动分类后可改回普通视频，无需重扫。分类保存到本机资料，不移动原件。标签页显示实际标签数量；没有标签时可直接按已扫描文件夹名称创建目录标签，也无需重扫。没有 NFO 的普通资源仍可从“视频”和“资源管理”浏览；照片日期与尺寸仅展示已经扫描到的信息。更细的按日时间轴、完整相机EXIF展示、电影系列自动识别、播放进度与批量重命名仍是后续功能，本版不把缺失信息伪造为已识别。

排序、翻页或切换照片墙／月份布局会保留勾选；改变搜索或筛选范围仍会清空勾选。刷新后，取消收藏、移出合集或已不属于当前核对结果的项目会自动退出批量选择，避免处理已不在列表中的文件。确认一组照片不相似时，其他组的勾选继续保留。

保存标签、收藏、评分或备注时，保存按钮暂时禁用；切换到下一张或关闭后，旧响应不会跳回旧媒体或把旧提示写进新详情。保存标签后继续输入的内容保留为未保存草稿；写入成功但刷新失败会明确提示，保留输入供核对。整理模式的删除和选择按钮在保存完成后自动恢复，无需再刷新。

媒体中心收藏覆盖、本地标签、目录标签绑定、自定义合集与最近打开保存于本机 `media-center.json`，使用私有原子写入和跨进程锁，纳入资料库备份；恢复快照可浏览，但重新扫描前禁止打开、清理其中原文件。源码版重启本机服务并刷新页面后使用新布局；没有新增依赖，也未自动下载安装包。

## 独立应用与安装包

两端沿用同一套 Python 后台、网页界面与 Pillow/FFmpeg 媒体组件。独立版本使用 **pywebview 原生窗口 + PyInstaller 内置 Python 3.12**，不用安装 Python，也不用保持终端运行。参考项目的资料库与桌面管理思路已用于本工具；没有复制它们的 GPL 源码，也没有拆成两套业务应用。

- **macOS：**在仓库 Actions 最新通过的运行中下载 `desktop-macos-latest`（Apple Silicon）或 `desktop-macos-15-intel`（Intel）产物，解压得到 DMG，打开后把 `MediaOrganizer.app` 拖入 Applications，再双击启动。
- **Windows 10/11 x64：**下载 `desktop-windows-latest` 产物，解压并运行 `MediaOrganizer-Windows-x64-Setup.exe`，安装到当前用户目录，从开始菜单启动。窗口使用系统 WebView2，需要 [.NET Framework 4.8](https://dotnet.microsoft.com/download/dotnet-framework/net48) 和 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。较旧 Windows 缺少时须手动安装，不会在扫描时联网补装。
- **签名状态：**当前 Mac 包只有本机 ad-hoc 签名，没有 Apple 公证；Windows 包没有发布者证书。系统可能要求确认来源。源码入口仍可用，两端行为相同。

独立应用资料保存在 Mac 的 `~/Library/Application Support/MediaOrganizer/reports`、Windows 的 `%LOCALAPPDATA%\MediaOrganizer\reports`；升级、卸载应用不会自动删除它们。源码版继续使用项目 `reports/`。两者互换资料时使用下面的备份恢复，恢复后重新选择本机来源并扫描。启动诊断保存在资料目录的 `desktop-session.log`，每次启动更新；打包程序会为原生组件保留有效的 UTF-8 输出流，不依赖可见终端。关闭原生窗口与页面“退出本机服务”走同一安全退出流程；有正在执行的文件操作时会拒绝退出，先完成或安全停止它。源码版 `.app` / `.command` / `.bat` 仍打开浏览器界面，与安装版功能共用。

从源码生成安装包时，在目标平台安装 `requirements-desktop.txt`，运行 `python build_desktop.py`；Mac 再运行 `python packaging/macos_package.py`，Windows 用 Inno Setup 6 编译 `packaging/windows.iss`。构建必须在对应操作系统完成。Python 3.9/3.12 可选安装原生窗口组件；当前 Windows pythonnet 不支持 Python 3.14，所以 **3.14 源码版使用同功能浏览器入口**，不安装 pywebview。发布的两端独立包均内置 Python 3.12，不受本机 Python 版本影响。Python 3.9 的 Mac 桌面依赖限定 PyObjC <12，避开错误的兼容性元数据。

扫描进度在页面顶部和媒体库页面同时显示当前阶段、已处理/总数与阶段百分比；清点目录时总数未知，显示已发现文件数和不定进度条。完整哈希的大文件另显示当前文件的字节进度，照片/视频解析、预览生成和导出分别展示，不能把阶段100%当作整个扫描完成。取消或失败保留真实状态，不伪造总体百分比或剩余时间；Mac/Windows与独立应用共用同一进度协议。

## 长期资料库、目录合集与备份

“长期资料库”将历次完整扫描结果汇入本机 JSON 索引，按路径保存最新记录，支持照片/视频、文件名/路径、目录层级和变化状态筛选；每页 50 项。同名文件夹保留完整路径区别，Windows 盘符、网络共享与 Mac 路径都能显示。点击“查看扫描快照”打开当时的照片墙或影片海报墙。未连接的其他磁盘记录会保留；索引仅缓存报告，不用于绕过原文件身份检查或 SHA-256 校验。

“新增”表示该路径首次出现；“变化”根据本次报告里的大小、修改时间或已有 SHA-256 比较；“仍在清单中”表示下一次扫描仍有相同记录；“本次未扫描到”可能是移走、跳过或读取失败，不证明文件被删除。来源范围不同的磁盘不会互相清空记录。所有状态来自快照，不是即时文件监控。

已添加的扫描目录会记住。Mac / Windows 均可在左侧“设置 → 目录自动更新”开启“目录变化后更新”：每15秒检查文件名、大小、时间与身份，连续两次结果稳定后自动只读扫描，首次开启或重启后会更新一次。新增、修改、移走文件及子目录变化均可触发；仍在复制的文件会等待稳定。后台完成后显示“目录清单已自动更新 · 查看新结果”，点击后切换新结果，不打断正在浏览、播放或确认的页面。磁盘断开、目录不可读或变成链接时暂停检查并保留当前资料库。不是即时系统事件监听；每次检查最多20万个目录项、128层及20秒（阻塞中的系统调用无法即时中断），超限可缩小目录或改用定时更新。也可选择“按固定时间重扫”，设置1–1440分钟间隔。默认关闭，退出后停止；不自动删除、移动、复制或改名，扫描进行中不启动另一份。重启后使用默认扫描选项。

**Mac 与 Windows 共用变化更新逻辑：**每次仍遍历所选目录、重新检查大小、时间和文件身份，发现新增、变化及本次未扫描到的项目。来源集合与解码组件版本相同、身份未变化时，复用上次完整本地报告的照片日期、dHash、照片小图、视频时长/尺寸和视频封面，减少重复解码；不复用文件 SHA-256，同大小精确查重候选每次仍完整读取。不是实时目录事件监听，也不会跳过目录遍历。缓存小图先检查有界 PNG 结构、尺寸与 CRC；损坏、截断、尾部多余数据或缺失时重新生成（此检查不代替媒体解码验证），旧格式及恢复快照不作为解析缓存。组件变化自动失效；需要重新解码可在新建扫描勾选“重新解析全部媒体”，命令行使用 `--refresh-media`。身份未变化不能证明字节一定未变化（例如刻意恢复时间属性），缓存只用于浏览与相似候选；不能据此清理。大文件完整查重仍可能耗时。

点击“下载备份 ZIP”保存报告、生成的小图、标签、已观看、收藏、评分、备注、影片分组修正、用户名与媒体归属、整理计划及操作记录；**不包含原始照片与视频**。单份压缩包最多 64 MB、解压最多 512 MB、10000 个资料文件；过大时保留原资料并提示分库保存。扫描或文件操作进行中不能备份/恢复。目录合集与定时设置存于 `workspace-settings.json`。

恢复先选择 ZIP，检查 SHA-256、允许的文件清单、路径和大小，显示预览，再点击“确认恢复为独立副本”。不会覆盖当前库或改动原媒体；恢复副本位于 `reports/restored-日期-随机标识/`，`active-workspace.json` 记住当前副本，原库保留。恢复的页面会重新生成，不执行备份中携带的 HTML。恢复后关闭自动更新并清空本机来源选择；**备份快照仅浏览，重新扫描前禁止操作其中的原文件**。标签、评分等资料仍保留。要切回原库，退出应用后备份并移走 `active-workspace.json`，不要改动媒体路径。

## 本地影片资料与剧照

默认只读取同目录、唯一关联影片的 UTF-8 NFO（`movie` / `episodedetails`），展示标题、年份、简介、演员、类型、导演和本地资料标签，并可通过海报墙搜索。个人标签和评分单独保留，不被 NFO 覆盖。多个 NFO 对应同一分组、格式错误、文件变化或超过 1 MB 时加入读取问题；拒绝 DTD/实体声明，不访问 NFO 中的封面网址，不联网抓取资料。

已有本地海报继续优先使用；“影片详情”同时显示同一影片目录的 `extrafanart/` 下已扫描图片、`fanart` / `backdrop` 或 `-fanart` 图片的小预览，点击放大。目录必须只对应一个影片分组，避免同目录多部影片串图；每组最多 8 张、每次最多 200 张。预览写入报告，不改动原图。图片解码失败列入问题；`--no-image-metadata` 关闭图片预览，`--no-local-metadata` 关闭 NFO 和剧照，Mac/Windows 参数相同。视频可从媒体中心详情按需页内预览或用默认播放器播放；当前不提供悬停播放片段或在线刮削。

## 开始使用

1. **macOS：**首次使用先双击 **`安装媒体依赖.command`**，再双击 **`媒体整理助手.app`**。它会通过终端启动本机服务，并在默认浏览器打开图形控制台；终端窗口需要保持打开。也可以直接双击 `开始扫描.command`，效果相同。
   **Windows：**首次使用先按下方步骤安装依赖，然后双击 **`开始扫描.bat`**。
2. Mac / Windows 首次进入可直接点击“添加媒体文件夹…”打开目录选择；已有资料库时，从左侧“媒体库 → 添加文件夹…”继续添加。选择后会显示下一步提示，核对目录再点击“开始只读扫描”；取消目录选择不会启动扫描。首次使用建议先选一个较小目录。
3. 点击“开始只读扫描”。完成后进入媒体中心，从左侧切换电影、视频、照片。
4. 点击卡片查看详情。电影可查看本地资料并播放；照片可放大和连续浏览。喜欢的内容在详情点“收藏”，也可以添加本地标签。
5. 在“相册与合集”创建合集，再到媒体页面主动打开“整理模式”，勾选后加入合集。需要清理时也在整理模式选择文件，预览后确认移到废纸篓 / 回收站。
6. 日常去重进入侧栏“重复与相似”，对比后勾选批量清理；高级查重与分类复制位于“整理工具”。批量改分类等旧功能仍保留，复制整理先预览、保留原件。文件变化后重新扫描刷新资料库。

使用工作台或编辑标签时请保持启动的终端窗口运行；在控制台点击“退出本机服务”会停止页面访问，已保存标签和核对进度不会消失。以后再次双击应用即可继续查看历史扫描，无需重新扫描；选择左侧“电影”可查看影片并编辑标签，`打开资料库.command` 也可单独打开最近一次资料库。

支持 **macOS 和 Windows 10/11**，需要 Python 3.9 或更新版本。**一套 Python 业务代码、同一网页界面、同一套默认图片/视频后端**，系统差异集中在平台适配层。两端安装脚本都在项目内创建 `.venv`，启动入口优先使用该环境；默认共用 Pillow / HEIF 图片解析与 FFmpeg 视频截帧，依赖统一定义在 `requirements.txt`。图形控制台由 Python 标准库在本机 `127.0.0.1` 提供，无须第三方网页服务；Windows 文件夹选择器需要 Python 安装器默认包含的 Tcl/Tk。若 Mac 应用打不开，可运行 `./.venv/bin/python media_gui.py`；命令行扫描仍可用 `./.venv/bin/python media_scan.py --edit-tags`。扫描过程中可点击“取消扫描”，不会改动原文件；导出阶段取消可能留下未完成报告。

未安装共用媒体依赖时仍可只读清点和精确查重。Mac 保留 ImageIO / AVFoundation 原生降级组件，图形界面会明确提示降级并按需尝试本机 `swiftc` 编译；其解码范围、相似判断和截图尺寸可能不同，不属于完整双端一致模式。安装媒体依赖后即优先使用共用组件，无须 Swift 编译器。原生组件源码继续保留。

macOS 终端的绝对路径必须从开头的 `/` 写起，例如 `open "/Users/你的用户名/项目目录/媒体整理助手.app"`；Windows 使用带盘符的绝对路径，例如 `D:\照片`。

## 省心整理（Mac 与 Windows 相同）

扫描完成后打开“整理管理”或“照片管理”，顶部选择独立目标文件夹，点击 **生成整理预览**，核对一次后勾选确认并开始复制。无需逐个选文件或先“纳入计划”。本入口准备本次报告的全部媒体，不受下方文件夹、类型和搜索筛选影响；要仅整理部分文件，继续使用下方手动流程。

- **照片 → `照片/年/月/`**：使用扫描时保存的年月，优先 EXIF 拍摄日期，其次文件名日期、最后修改时间；缺少有效年月进入 `照片/待确认日期/`。唯一 RAW/JPEG 配对优先采用有拍摄日期的成员，再采用 JPEG 的日期。年月的降级依据会在预览中提示，不读取观看电脑的时区重新推算。
- **家庭视频 → `家庭视频/年/月/`**：未与照片配对、相机前缀加数字（IMG/VID/DSC/PXL 等）且没有影片编号、字幕或 NFO 依据的视频按家庭视频候选整理；不分析内容来判断。日期使用手动修正、有效文件名日期或扫描记录的 UTC 修改时间，无法确定时进入待确认日期。普通未识别名称仍作为待确认电影，可手动修正视频类型。
- **电影 → `电影/国产、日韩、欧美、其他/作品名-标识/`**：优先本地 NFO 的 `<country>`，没有时只匹配明确的原文件夹名称。中国大陆、香港、台湾等归国产，日本和韩国等归日韩；跨大类合拍或没有唯一依据进入 `待确认地区`。这是一组离线常用地区映射，不通过文件名、语言或演员猜国家，不联网刮削。旧报告没有地区字段时，重新扫描才能读取 NFO 国家。
- 明确关联的字幕、NFO、封面和剧照跟随电影，RAW、唯一同名视频候选、XMP、AAE 跟随照片；同名视频不代表已验证的 Live Photo。有明确影片编号的同名图片按电影封面处理；手机相机编号不作为影片编号。配套歧义集中列出，不能自动解决的组不加入。照片同名时添加稳定的来源标识子目录，保留配套原文件名；大小写、Unicode 等价、文件与目录冲突都要核对。
- 已暂缓、手动调整过分类位置、缺少身份记录、目标已存在或来源变化的组跳过并说明原因。已有成功记录的整组不重复复制（即使换了目标目录），请核对原目标；曾失败或结果不明的文件不会自动重试。组只完成一部分时须手动核对剩余项。
- **默认整份清单确认一次，自动分批复制**：每批最多 200 项、整组不拆，单次确认最多 10,000 项（含附件）。预览显示总数、分批数与剩余未进入本次确认的数量，完整确认清单每页 100 项。取消勾选“自动分批”仍可只处理一批；单组超过 200 项须手动拆分核对。没有可执行文件不能启动。预览与取消不修改原媒体、分类决定或目标目录。
- **整理检查清单**：默认只显示需要处理的问题；整组全部文件有成功操作记录、主动暂缓的组分别计数，可切换状态查看。只处理了一部分、失败或结果不明的组仍列为需处理，不会自动补复制。分类依据是操作记录，不代表副本仍存在或已检查当前状态。支持媒体类型、搜索、原因筛选与每页 50 项；CSV 导出始终包含全部检查记录及状态，不受当前筛选影响。
- **批量修正**：可一键勾选当前筛选结果的前 200 个可修正媒体（跨页），附件、已有成功记录和暂缓项不纳入；超出数量会明确提示。翻页保留勾选，切换筛选会清空问题勾选；下方手动媒体勾选独立保留。修正电影地区或视频类型时先筛选“视频”。展开“批量修正分类”，选择地区、年月或视频类型后只显示相应输入，也能恢复自动分类。修正原子保存，同一作品全部版本的地区/类型同步，明确 RAW/JPEG 配对的年月同步；修正后重新预览，不修改原文件日期、NFO 或手动整理计划。
- **记住设置**：点击“记住当前整理设置”，按当前扫描来源集合分别保存目标目录和自动分批开关。来源目录仍由主控制台记忆。分类修正按原路径保存，后续扫描继续使用；外部搬动或改名后须重新核对。设置保存在 `organize-settings.json`，纳入资料库备份。记忆的路径每次使用仍重新检查，不自动发起复制。
- **整理后的文件夹**：按本报告的成功复制记录，从实际目标目录逐层进入，可点击路径导航返回任一上级。支持照片、视频、附件筛选和名称自然顺序／逻辑大小排序；默认包含子目录，可关闭后只看当前层，搜索始终覆盖当前目录及子目录。文件夹每页 30 个、副本每页 50 项，显示匹配数量与逻辑大小；刷新保留目录、筛选和页码，重置可回到全部结果。所有筛选只影响这里的浏览，不改变整理计划或复制范围。点击照片缩略图可按当前目录、筛选和排序连续预览，跨分页使用上一张／下一张或左右方向键；关闭后保留列表位置，浏览不会改变勾选。预览明确显示副本路径，可打开或定位整理副本；视频仍由默认播放器播放。缩略图和放大预览沿用扫描时的小图，不代表副本当前内容。旧副本记录也能查看已有扫描预览，但缺少身份记录时不提供打开动作。打开前检查副本身份，拒绝被替换、修改或变成链接的路径；旧记录缺少副本身份时只能查看记录，需要重新扫描目标目录。这里不遍历目标磁盘，外部新增、删除或移动不会自动反映。

Mac 与 Windows 共用这套界面、分类与队列。整份清单确认后，不再为其中的每一批重复弹窗；整个任务持续持有操作锁，每批保留独立日志，来源身份与目标不覆盖仍逐文件检查，副本使用完整 SHA-256 校验。单项失败、结果未确认或日志异常会停止后续批次，不自动重试。可随时安全停止，已完成副本保留；关闭或重启服务不会自动续跑，须核对记录后重新预览。执行期间保持本机服务运行。原件不移动、不改名、不删除，精确重复清理和相似图片候选规则不变。

## Windows 安装与运行

1. 安装 Python 3.9 或更新版本，保留安装器默认的 **pip、Tcl/Tk**，勾选 **Add Python to PATH**。建议使用 Python 3.12 或更新版本。
2. 双击 `安装Windows依赖.bat`。它只在项目内创建 `.venv` 并安装依赖，不改动系统 Python；首次安装需要联网。
3. 双击 `开始扫描.bat`。浏览器会打开同一整理工作台；保持启动窗口运行。可重复点击“添加文件夹…”选择多个来源。
4. 以后双击 `打开资料库.bat` 可查看最近一次影片资料库，无须重扫。省心整理可自动准备复制清单，预览确认后执行；手动复制和清理仍须选择文件并确认。

也可以在项目目录的 PowerShell 中运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
.\.venv\Scripts\python.exe -X utf8 media_gui.py
# 命令行只读扫描示例
.\.venv\Scripts\python.exe -X utf8 media_scan.py "D:\照片" "E:\视频" --open
```

两平台使用 Pillow 读取照片日期、生成缩略图与 dHash，pillow-heif 补充 HEIC/HEIF 支持，imageio-ffmpeg 提供随包附带的 FFmpeg 用于视频时长/尺寸读取与截帧，不需要单独安装 FFmpeg。共用代码统一 EXIF 方向、相似指纹计算、缩略图尺寸、视频候选格式和截帧策略。部分 RAW 或特殊编码仍可能无法解码，会保留文件清单与精确查重结果；解码失败不能证明文件损坏。平台、解码器版本或编码差异仍可能影响特殊格式，不能保证所有预览逐字节相同。视频信息只读取文件头描述，每个文件有超时限制；失败时保留浏览与精确查重，记录读取问题。硬链接别名暂不重复解析。未安装 FFmpeg 的 macOS 原生降级仍可生成封面，但时长/尺寸显示未知，安装共用依赖后重扫补充；Windows 缺少 FFmpeg 时也显示未知。未安装媒体依赖时，仍可执行 `--no-image-metadata` 的只读扫描。

Mac 也可在项目目录的终端中手动安装并运行：

```sh
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python media_gui.py
```

`requirements-windows.txt` 保留为旧入口，转引同一份 `requirements.txt`；Windows 回收站依赖通过平台标记安装，Mac 不会安装 Windows COM 包。扫描不会自动联网安装依赖。

Windows 打开原文件使用默认程序，定位使用资源管理器；清理使用现代 Windows Shell 回收站接口，需要 `Send2Trash[win32]`（安装脚本已包含）。不能确认可回收的文件会拒绝清理，不退回永久删除。macOS 打开原文件使用默认程序，定位使用 Finder，清理使用系统废纸篓；对应同样的打开、定位、预览确认和可恢复清理流程。

Windows 跳过符号链接、目录联接及云端重解析占位项；请先将需要扫描的云端文件下载到普通本地目录。分类建议在两平台都使用 `/` 分隔，屏蔽 Windows 保留名、非法字符及尾部空格/句点，实际复制时转换为本机路径。报告与媒体路径属于产生它的电脑，复制报告到另一台电脑可查看静态清单，操作原媒体前应在新电脑重新扫描。

Windows 文件身份结合设备/文件编号、大小、修改时间和创建时间；macOS 使用设备/inode、大小、修改时间和状态变化时间。Windows 报告文件继承所在目录的访问控制，macOS 保持原有 POSIX 私有权限。

## 查重方式

- **精确重复**：先按大小筛选，再完整读取候选文件计算 SHA-256；只对内容相同的非空文件分组。大小唯一的文件不必哈希，状态会写入清单。
- **硬链接**：多个路径指向同一物理文件时单独标记，不重复计入副本大小。
- **相似图片**：系统图片组件生成 64 位 dHash，默认距离不超过 6，且宽高比差异不超过 8%。纯色和低细节图跳过比较，动画只比较第一帧。报告为前 300 对候选生成本地小预览图，方便并排核对。只有发现超过候选数量上限时才标记结果不完整。结果只是人工检查候选，不能据此删除。裁剪、旋转、颜色变化、连拍可能误报或漏报。
- **视频**：支持完全相同的文件查重；另按相同编号或去掉常见分段、画质标记后的标题列出“相关视频候选”，并展示大小、文件修改时间和 SHA-256 校验状态。`-C`、`-CH` 字幕变体与 `CD2`、`DISC2`、`PART2`、`PT2` 分段仅显示为文件名标记，不证明实际有字幕或可播放。相关候选不代表内容相同；不识别重新编码、剪辑或不同分辨率的同一视频。可选用 `--check-video-headers` 读取每个受支持视频的前 32 字节，提示 MP4、MOV、M4V、3GP、MKV、WebM、AVI、FLV 的常见容器头是否可识别；这不能证明视频可播放，其他格式保持“未检查”。默认不开启，以免对云盘占位视频增加读取。

“多余副本大小”为逻辑字节估算；APFS 克隆、压缩、云盘等会让实际可释放空间不同。扫描期间文件变化或不可读会列入问题报告。结果只代表成功扫描的范围。

## 影片资料库

每次扫描都会在报告目录生成 `library.html`。它按作品和版本归组影片，作品默认依编号判断；没有编号的影片只在同一原目录内按名称归组，避免不同目录的同名视频被误并。海报墙可以搜索编号、影片名、路径、标签和附属文件，并筛选待核对、精确重复、有附属文件、有封面或缺少封面的影片。

海报墙支持按原文件夹、标签、观看状态和个人评分组合筛选，也可按名称、整组大小、文件修改时间或个人评分排序。原文件夹显示完整路径，区分不同磁盘上的同名目录；跨目录分组只要有一个文件匹配，仍展示该影片的全部版本或分段。每组大小为全部视频文件的逻辑字节数，可能重复计入硬链接；修改时间取组内最新文件的扫描时间记录，不代表上映、入库或观看时间。评分保存后立即更新筛选和排序，缺少时间的旧报告分组排在时间排序的末尾。“重置筛选”清空搜索和各项条件，并回到第一页。待核对清单只跟随搜索词，不跟随海报墙的其他条件。两平台使用同一套浏览逻辑；静态 HTML 也能筛选和排序，评分编辑仍需本机服务。

Mac 与 Windows 共用作品、版本、分段逻辑。文件名的 1080p、2160p/4K、编码、来源、HDR/DV 和字幕变体标记用于区分版本，CD/PART/DISC/PT 用于分段排序；这些是线索，不证明实际画质、字幕或片段内容。不同线索默认分组，缺少线索标为未指定；同版本重复段号或不连续段号会提示核对，不据此清理。

海报墙点击“修正作品、版本和分段”，可逐文件选择现有作品或新作品名、修改版本及段号。相同作品与版本合并，不同版本拆开；勾选“恢复此文件的自动分组”取消修正。只修改 `reports/library-grouping.json`，刷新后生效，新扫描继续使用，并纳入备份。一次最多 200 个文件；标签、评分、备注仍按作品共用，同一作品的多个版本会同步显示，新作品不自动继承旧标记。修正按原文件完整路径记住，外部改名或搬动后需重新修正。旧报告的封面或 NFO 在拆组后归属不明确时暂不沿用，重新扫描会按新组重新关联；静态 HTML 是扫描快照，修正须从本机服务打开。Mac 和 Windows 都会在保存锁内核对分组版本；另一窗口已修改时拒绝旧页面提交，提示刷新，不覆盖已保存修正。

从图形控制台打开海报墙后，单文件影片可以直接点击“播放”；分段或多个版本请展开文件列表，选择具体文件。使用系统默认播放器，不内置播放器、不转码；格式支持取决于已安装的播放器。照片同样交给系统默认查看程序。“在文件管理器定位”会选中磁盘上的原文件。

卡片上可以手动“标记已观看”或“收藏”，也可取消标记；筛选菜单支持“未标记已观看／已观看／收藏”。这些标记作为标签与自定义标签一起保存，重新打开及新扫描继续读取。打开影片不会自动标记已观看；同编号影片的不同版本或分段共用观看标记。

“影片详情”集中列出分段或版本文件、大小、修改时间、字幕等已关联附属文件、精确重复与读取问题，并提供播放和文件管理器定位。可以设置 1–5 星个人评分（0 为未评分）及最多 2000 字观看备注，保存于 `reports/library-notes.json`，从本机服务重新打开或新扫描后保留，也可搜索备注。同编号影片共用评分与备注；无编号影片按原目录与名称保存，改名或搬动后需重新设置。本地 NFO 的演员与简介展示在同一详情中，不抓取在线评分。

**附件完整性核对（Mac / Windows 一致）：**影片详情显示该作品版本的视频、字幕、NFO、封面、剧照文件数量，可展开已关联附件与待人工核对清单。与整组复制预览共用关联规则；同目录其他作品已唯一关联的附件不会误报为本组问题。未发现字幕、NFO、封面或剧照只表示缺少可选资料，不表示影片损坏；数量按文件计（例如 IDX/SUB 是两个文件）。检查只读取已有扫描报告。旧快照若缺少清单或身份记录，请重新扫描。

封面优先使用同目录与影片或编号同名的图片，也识别 `-poster`、`-cover` 后缀；仅当一个目录属于同一影片分组时，才使用 `poster`、`folder`、`cover` 等通用名称。没有本地封面时，两端默认用共用 FFmpeg 后端截取视频约 10% 位置的一帧，无法获取时长时尝试开头，缩放至最大 512×512 并保持比例。两端都对支持清点的视频扩展名尝试截帧，包括 MP4、MOV、MKV、AVI、WebM；单次默认最多为500个未命中缓存的影片分组新截帧，已验证的缓存封面不占此额度。不支持、无法解码或超过上限时显示占位图。海报小图只生成在报告目录 `covers/` 中，不改动原图或视频。截帧不代表真正的官方海报，也不能证明视频完整或可播放。可在 Mac / Windows 扫描设置取消“读取视频时长、尺寸与封面”，或用 `--no-video-covers` 关闭视频信息读取与截帧，或用 `--max-video-covers` 调整上限；`--no-image-metadata` 会连同封面解码一起关闭。`report.json` 的 `options.image_backend` / `video_backend` 记录该次选择的组件，便于区分共用模式与原生降级路径。

在图形界面打开的本机资料库页面中，点击影片卡片上的“编辑标签”，用逗号分隔多个标签；清空输入可删除标签。标签立即保存到 `reports/library-tags.json`，新一次扫描会继续读取。同编号影片共用标签；无编号影片按原目录与名称保存标签，改名或搬动后需重新设置。直接双击旧报告的 `library.html` 仍可查看扫描时的标签，但编辑需要从图形窗口或 `.command` 入口打开本机服务。

待核对清单汇总视频读取与可选文件头检查发现的问题、完整 SHA-256 确认的重复视频、未唯一关联的字幕/NFO，以及同名文件夹候选。页面展示与搜索词匹配的前 200 条，完整清单在 `library_issues.csv`。未启用 `--check-video-headers` 时不检查视频容器头；即使识别到常见文件头，也不能保证可播放。没有字幕/NFO 不自动视为问题。

资料库使用本次扫描的快照；新增、修改或移走媒体后需重新扫描。打开与定位前会检查文件是否仍是扫描时的文件；磁盘未连接、路径变为符号链接或文件变化时提示重新扫描。旧报告从本机服务打开时也会使用当前资料库界面；字段不足的旧报告仍可浏览，但不提供文件打开按钮。直接双击 HTML 只显示静态快照，不提供打开、定位、观看标记、评分备注与标签保存。工具不在线抓取资料，也不自动清理原片。

## 按用户名管理照片与电影

Mac 与 Windows 的工作台都有“用户名分类”入口，照片墙、影片海报墙及文件整理页也可进入。用户名是手动建立的媒体分类名称，支持新增、搜索、改名和确认删除；每张照片、每部电影只分配给一个用户名，或保持“未分配”。电影的全部版本和分段一起分配；重新分组后如不同文件的归属不一致，会显示“归属不一致”，需重新选择整部电影的用户名。可按用户名、媒体类型、名称或原路径查询，并展开原位置打开照片、播放电影或定位文件。照片墙与文件列表也可直接按用户名筛选、显示归属，沿用勾选后批量保存归属；海报墙勾选任一版本即选择整部电影，全部版本和分段一起归类。两种墙面都提供“刷新用户名”；其他窗口改名或分配后，刷新可同步，旧窗口保存会被拒绝。

勾选照片和电影，选择用户名后点击“保存勾选项归属”。改名保留归属；删除用户名解除历次记录中的对应归属，不删除媒体。用户名限 1–60 字，须符合两平台文件夹名称规则；大小写与 Unicode 等价名称不能重复。最多 1000 个用户名、200000 个媒体文件归属，每次分配最多 200 项。用户名与归属保存于资料目录的 `media-users.json`，随备份恢复，重新扫描相同原路径可继续读取。外部改名或搬动媒体后需重新分配；这些名称不是系统账户，也不提供登录或访问权限隔离。

“预览按用户名分类”支持三种照片目录：默认 `用户/用户名/照片/年/月/当前建议文件名`，也可选择按年份或同一照片目录。年月沿用扫描报告中照片的原始分类日期，不受手动修改整理计划目录影响；预览列出日期来源（EXIF、文件名推测或修改时间回退），缺少日期归入“日期未知”。电影生成 `用户/用户名/电影/作品-标识/版本-标识/原文件名`，没有版本时省略版本目录；作品和版本标识用于区分同名目录。电影展开全部版本和分段，计划每批最多 200 个媒体文件。

同名照片默认在预览中提供路径标识后缀建议，例如 `旅行-12ab34cd.jpg`；检测大小写及 Unicode 等价重名，同时避开本次报告未勾选文件的建议目标。后缀过长时缩短主文件名，保留扩展名以满足两平台名称长度限制。也可选择“遇到重名停止”。**同名不表示内容相同，后缀不是内容哈希**；精确重复仍依据完整 SHA-256，图片相似仍只作为候选。电影保留原文件名以保留附件关联，文件与目录路径冲突仍拒绝整批。此处仅检查报告内的分类目标；真正复制时仍检查磁盘已有文件，目标不覆盖。

确认保存仅改当前扫描的分类计划；点击“打开本批整理计划”，核对并纳入后再预览确认复制。影片附件仍须选择“影片和附件整组复制”；照片配套文件选择“照片和配套文件整组复制”，并保持原文件名。用户名、归属、扫描日期或整理计划变化后，旧预览拒绝保存；改变模板或同名建议也须重新预览。用户名改名或重新分配后，可重新生成选中媒体的计划，在预览中核对旧目录与新目录；不会追改已复制的文件。

用户名改名、删除或重新分配后，旧分类计划和已复制目录保持原样；需要用新用户名重新生成计划。归属与计划编辑沿用跨进程锁，文件操作执行中暂停修改。恢复的备份快照可管理归属和查看计划，操作原媒体仍需重新扫描。

## 照片浏览与磁盘状态

新扫描默认为前 500 张照片及总报告中显示的相似候选生成报告内预览图。照片墙可搜索、按年月或原文件夹筛选、多选和并排比较；超过预览范围或不能解码时显示占位提示，仍能打开原图。未启用图片解析时不生成预览；旧扫描缺少预览时可以重新扫描。缩略图不会替代原图，也不表示图片内容完全相同。

**照片连续浏览与整理排序（Mac / Windows 一致）：**文件列表和照片墙支持名称自然顺序、逻辑大小、文件修改时间从新到旧或从旧到新；修改时间不是拍摄时间，旧报告缺少时间的项排最后，照片年月仍按原扫描的日期依据筛选。点击预览图后，可用“上一张照片／下一张照片”或键盘左右键浏览当前筛选的全部照片，包括后续页面；到边界停止，不循环，缺少小图仍显示占位并可打开原图。并排比较保留两张选择，不进入连续浏览。重置筛选会回到第一页、清空勾选，照片墙仍保持照片视图；从照片墙切换到视频筛选会进入列表并清除照片年月条件。打开、播放仍交给系统默认程序。

来源状态会检查所选文件夹是否可访问；不可访问可能是磁盘拔出、文件夹移走或权限问题，不据此删除记录。外接磁盘未连接时，历史清单和已生成的小图仍可在本机报告中浏览，文件打开与操作则提示不可访问。

“与上次扫描比较”寻找相同来源目录集合的较早报告（最多检查最近 50 份候选），列出新增、大小/时间/文件身份或已知 SHA-256 变化，以及本次未扫描到的文件。页面展示前 200 项。来源不同则不直接比较；“本次未扫描到”可能由跳过、读取失败或移走造成，不证明文件已经删除。比较不替代新一次扫描，当前仍会扫描并校验所选范围。

## 分类预览

“文件管理与整理”将全部照片和视频的分类建议集中展示，每页 50 项，支持按文件名、原路径、建议位置和分类依据搜索，也可按媒体类型、核对状态和建议目录筛选。默认显示待核对文件，已纳入和暂缓的文件可切换状态查看；查看所有文件时请选择“全部状态”。逐项标出精确重复组与硬链接，方便打开检查或在 Finder 定位后再决定如何处理；相似候选不会被当作精确重复。

核对重点筛选可单独查看分类位置有问题、精确重复涉及文件、硬链接或已调整位置的文件。顶部显示核对进度和问题数量，目录筛选显示对应文件数；“刷新进度”可读取其他窗口保存的最新结果，同时清空尚未提交的勾选。

“调整分类位置”可以修改计划中的相对目录与文件名，例如 `照片/家庭旅行/2026/旅行.png`，不会修改原文件或扫描报告。新路径必须有效且不能与其他目标重名（含大小写和 Unicode 等价名称），也不能让文件路径与目录路径冲突。位置有变化的文件会回到待核对，需要重新纳入；未变化的路径保留原核对状态。“恢复扫描建议”撤销该项的位置调整，也需重新核对。如果恢复后会与其他已纳入文件冲突，会提示先将相关文件恢复待核对。页面保留原扫描建议供对照，CSV / JSON 导出包含调整后的路径、原建议和手动调整标记。

每次扫描的核对进度与位置调整保存在该报告目录的 `organization-plan.json`，重新打开会继续读取，兼容旧版仅保存核对状态的文件。新扫描有独立进度。纳入前会检查相对目标路径、大小写及 Unicode 等价重名、文件与目录路径冲突；有问题的建议保持可见，但不能纳入，可调整后重新核对。批量保存要么全部成功，要么保持原状态；损坏或与报告不匹配的进度文件会提示错误并保留，不会静默覆盖。

“导出计划 CSV / JSON”只包含已纳入文件，暂缓和待核对项不导出；上方“导出清单”仍可下载全部媒体、重复、相似和读取问题清单。导出按钮仅保存计划，实际复制须通过“预览复制分类”独立确认，成功时才创建对应分类目录。

- 照片：`照片/年/月/照片或截图或RAW或动图/原文件名`。
- 日期依次取 EXIF 拍摄时间、文件名里的有效日期、文件修改时间。修改时间不一定是拍摄日期，报告会明确标注。
- 视频默认优先识别类似 `ABC-123` 的编号，建议归入 `视频/编号/ABC-123/`。分段、字幕和画质标记保留在文件名中；同编号不等于重复。
- 无编号的视频优先保留子目录层级；扫描根目录下的视频按名称建议归组。可指定按名称或原目录整理。
- 与照片同目录同名的 MOV/MP4/M4V 提示可能是实况照片配对视频，需要人工确认；若同名照片不止一张，则保留在视频分类并标出配对不明确。XMP、AAE、字幕及 NFO 会列在附属文件清单中，只按同目录文件名寻找对应媒体；支持 `Film.mp4.zh-CN.srt`、`Film.en.srt` 等名称。若文件名写明 `.mp4`，只关联 MP4，不会误配同名 MKV。多项候选和孤立文件会明确标记。可读取本地 NFO 资料；普通操作不处理附件，整组复制会明确预览附件。不会移动或修改原附件。
- 报告会列出同名文件夹，以及不同原名经过安全化后变成同一建议名称的文件夹，同时显示媒体和附属文件数量。若两个互不包含的文件夹下所有已扫描媒体都取得完整 SHA-256，且媒体字节内容集合一致，会给出一个匹配文件夹示例；哈希不足时标记“未确认”。这只比较已扫描的媒体；附属文件只计数，不比较内容，其他非媒体文件和跳过项也未比较，因此不能据此认定整个文件夹完全相同。保留原目录的视频建议遇到同名扫描根目录或同级目录名称冲突，会给目录加来源路径标识，避免不同来源混在一起。
- 重名目标文件会追加来源路径标识，避免建议里出现互相覆盖。建议不是已创建的目录，也不会自动执行。

## 实际整理与可恢复清理

展开文件管理页顶部的“空间分布与大文件”，可按扫描来源、原文件夹、照片/视频、照片年月查看逻辑大小与比例，或查看最大的 100 个媒体文件，每页 20 项。原文件夹只汇总直接位于该目录的媒体；扫描来源汇总其子目录。点击“查看这些文件”跳到对应清单并按大小排序，大文件可直接手动加入清理候选篮。统计只读取扫描报告，不重新读取原媒体；不含未扫描文件和附属文件，硬链接可能重复计数，也未统计压缩或稀疏文件的实际分配空间。精确重复副本大小只计算报告中有效的完整 SHA-256 分组，与图片相似候选分开；这些数字不代表能立即释放的空间。照片年月沿用扫描分类，日期可能由文件名或修改时间推测。操作后请重新扫描。

“清理候选篮”可把不同搜索、类型、原文件夹或分页里的照片和视频集中保存。勾选后点击“将勾选项加入候选篮”，也可从大文件列表逐项加入；候选记录属于当前扫描，最多 200 项，刷新页面或重新打开仍保留。点击“查看候选篮”逐项核对，或“勾选候选篮可处理项”明确勾选全部可预览成员；候选篮中的勾选跨页保留。“移出候选篮”和“清空候选篮”只改候选记录，原媒体不变。实际清理仍走独立预览、勾选确认和执行流程，精确重复组至少保留一份，不能把相似照片当作已确认重复自动清理。

多个窗口或本机服务修改候选时会在保存时读取最新记录并合并增删；“刷新候选篮”同步其他窗口的结果，重新聚焦页面时也会读取。候选视图里已被其他窗口移出的成员同时取消勾选；新加入的成员不会自动勾选。成功清理的候选保留记录并标记，可手动移出，重新扫描不会沿用旧篮子。记录私有保存在本次报告的 `cleanup-basket.json`；损坏、符号链接、报告不匹配或超出上限时保留原文件并提示，修改不完整时不会覆盖原候选。执行文件操作期间暂停候选修改。

macOS 和 Windows 共用简洁界面：常用入口为“文件夹 / 照片 / 电影 / 重复文件 / 相似照片”，其余放入“更多”。文件浏览默认显示全部核对状态；“整理到新文件夹”和“高级选项”默认收起，原有手动分类、候选篮和导出功能仍可展开使用。

照片缩略图、文件列表、照片放大与并排对比窗口、精确重复分组的每份文件，以及影片文件旁均提供“删除…”按钮，直接预览所点文件，不替换已有批量勾选。点工作台“重复文件”直接进入可操作分组，选择保留项后也可预览清理其余副本。已有总报告中的重复项和相似照片，在本机服务打开时也会补上就地删除与双图对比按钮：弹窗复用相同预览确认流程，关掉后留在原报告。双击离线 HTML 仍是只读报告。所有“删除”均在确认后移到废纸篓 / 回收站；相似照片不自动勾选，完整 SHA-256 精确重复至少留一份，配套附件不会随单文件删除。

更新源码后须退出并重新启动本机服务，再刷新浏览器。

点击文件管理页的“按组核对精确重复”，可按完整 SHA-256 分组查看照片和影片的全部来源、修改时间及关联附属文件，按重复副本逻辑大小排序，每页 10 组。支持搜索路径/名称/完整哈希与照片/视频筛选；只匹配一份文件时仍展示整组。每组没有默认保留项，先点“选作本组保留项”，再“预览清理其余副本”；该预览清空其他勾选，弹窗明确列出保留路径和待清理路径，仍须再次确认才执行。保留选择仅在当前页面有效，刷新后重新选择。超过 50 个成员的组须展开完整列表后才能批量预览；剩余副本超过 200 项时，在主清单分批核对。硬链接、相似候选、校验信息缺失或矛盾的组不会当作已确认重复展示，问题会提示重新扫描。分组读取只使用扫描报告，不读取原媒体内容；清理前仍检查保留文件及副本的当前身份。逻辑大小不代表立即释放的空间。

刷新页面、重新打开整理页会自动读取正在执行的任务并恢复进度。同一报告的多个窗口共享状态；从另一服务查看时显示“另一服务执行中”。运行期间锁定分类位置与核对状态修改，并阻止同一报告在不同服务中重复启动批次。连接失败会锁定操作并自动重连；可点击“读取操作记录”立即重试。损坏的历史记录单独提示，其他记录仍可查看；需先核对问题记录后才能继续执行。强行中断的任务不会自动续跑。

执行记录里的“安全停止此批次”可随时请求停止，也可从另一整理窗口发出请求。复制在读取或校验时检查停止请求，清理当前未完成的临时副本，保留原件与已完成副本；目标可能留下空的分类目录。废纸篓操作会等待当前文件的系统调用返回，再停止后续项，不会强行终止或自动恢复已成功项。磁盘读取、写入或同步正在等待系统响应时，停止可能需要等待，请保持服务运行。记录显示“已安全停止”、成功/取消项，以及可展开的“未处理”清单。批次已结束时再点停止不会改变结果；系统结果未确认的项仍提示人工核对，不会当作已安全取消。继续整理时重新勾选、预览，已存在的副本仍不会覆盖。

停止后可点击“核对此批次未处理项”，只重新勾选未开始或已安全取消的文件，切到“只看当前勾选”列表供逐页核对。此按钮不执行文件操作，也不沿用旧预览；请核对当前分类位置、纳入状态与目标目录，再重新预览确认。检查本报告的全部有效批次，任何批次已有成功记录、曾失败或结果未确认的文件都会跳过，并列出原因；服务中断、记录写入失败、旧记录没有完整清单或历史损坏时，需要先人工检查。不会自动重试失败项或恢复已清理项。

文件列表与照片墙显示“已有复制成功记录 · 原件保留”和“已移到废纸篓”，可通过核对重点筛选查看已复制、已清理、没有成功处理记录或当前勾选。界面展示最近 20 个批次，文件标记覆盖本报告的全部有效操作记录，不受展示上限影响。标记表示历史记录，不保证副本现在仍在目标位置；通过 Finder 恢复原文件后，也需重新扫描更新清单。

**按文件夹管理照片和电影（Mac / Windows 一致）：**照片页和文件管理页新增“文件夹管理”，默认显示磁盘原有目录，可逐层进入子目录、返回上级或回到全部文件夹；也可切换“整理分类目录（计划）”查看用户名等建议目录。每个目录展示已扫描照片 / 视频数量、逻辑大小及子目录数量，相同名称按完整路径区分，不合并不同磁盘、父目录、大小写或 Unicode 名称。默认包含子目录，进入目录后可关闭“包含子文件夹”只看直接存放的媒体。进入目录会清空旧勾选并重置搜索、状态、用户名和目录等筛选，保留媒体类型与浏览方式；仍可继续搜索、筛选和打开照片 / 播放电影。

文件夹搜索支持名称或完整路径（不区分大小写，兼容 Unicode 等价搜索），搜索当前目录的全部下级目录，每页 30 项；不同原路径仍分开显示。点击搜索结果直接进入该目录并清空目录搜索。目录排序可按名称、含子目录的逻辑大小或媒体数量；搜索和排序只影响目录卡片，不改变下方媒体筛选、勾选或分类计划。磁盘原目录与分类目录分别记住本页会话中的位置、搜索、排序、子目录开关和目录页码，切换后恢复；浏览器刷新不保留这些位置，已勾选媒体也不随切换保留。目录从计划或媒体类型范围中消失时返回全部文件夹，重置筛选清除两种目录的记忆。

“勾选目录内筛选结果”只替换媒体勾选，跨越文件列表分页（最多 200 项），排除已有清理记录或没有本机媒体映射的项；超过上限时整批不勾选，请进入子目录或缩小筛选。勾选后可批量调整分类目录、核对纳入、预览复制或现有媒体清理流程。整组配套文件仍通过照片 / 影片的整组复制核对。本功能只读取扫描记录，不自动遍历实时磁盘；离线或历史快照可浏览，执行操作仍须新扫描的有效媒体身份。分类目录只是计划，不表示原件已经移到该位置；不提供整文件夹移动、删除、改名，也不处理未扫描文件、附属文件或空目录。操作后请重新扫描更新目录统计。

**批量调整分类目录（Mac / Windows 一致）：**勾选 1–200 个照片或视频，点击“批量调整分类目录”，填写相对目录（如 `照片/旅行`、`视频/待观看`），用 `/` 分隔层级。保留每项当前建议文件名，包括已手动调整的名字；不会展开整组影片或自动携带附件。先点击“预览分类调整”核对全部原路径、原建议和新建议，再“确认保存计划”。预览不写入，取消不改变计划；重名（含大小写与 Unicode 等价）、文件与目录冲突、不支持的双平台名称会拒绝整批。另一窗口修改了计划时须读取最新进度后重新预览。保存只改报告内计划，位置变化的项重新待核对，未变化及未勾选项保留状态；保存后展示本批勾选项，核对并纳入计划后才能预览复制。影片整组复制要求同组所有分段处于同一目录，请一并调整。没有自动复制、移动或原文件改名行为。

每页最多 50 个文件，可以逐项勾选或“全选当前页”，按页分批处理。“复制分类”要求先纳入计划，目标须是已存在的独立普通文件夹，不能位于扫描来源中或包含原媒体。预览检查目标空间、已存在名称、大小写及 Unicode 等价冲突和符号链接；确认后再次检查源文件、目标目录身份与分类计划。复制保留原件，副本逐项做完整 SHA-256 校验，不覆盖已有目标。

清理使用 macOS 原生 `FileManager.trashItem` 或 Windows Shell 的可恢复回收站接口，不会永久删除，也不清空废纸篓 / 回收站。需要当前报告记录的文件身份，较旧报告应重新扫描后再清理。同一精确重复组不能整组一起选中，执行前也会检查计划保留的副本是否仍可访问；相似图片不自动勾选或删除。恢复时在 Finder 废纸篓中放回文件，或在 Windows 回收站中选择还原。废纸篓 / 回收站仍占用磁盘空间，本工具不会承诺立即释放预览所显示的逻辑字节数。

**影片和附件整组复制（Mac / Windows 一致）：**在文件管理页只勾选视频，点击“预览影片和附件整组复制”。会展开该作品版本的全部视频，以及唯一关联的字幕/NFO、本地命名匹配的封面和独占影片目录的剧照（保留 `extrafanart/` 子目录）。每个视频必须先纳入同一分类目录，并保留原文件名以保持字幕关联；整组复制保留原扩展名大小写。确认页按组显示附件数量，逐项标明影片、字幕、NFO、封面、剧照，以及未明确关联而未加入的疑似附件；可取消。通用海报或剧照若被多个组共用，不自动选择。旧报告缺少附件身份记录时须重新扫描。展开后最多 200 项，目标重名（含大小写/Unicode 等价）或文件与目录冲突会拒绝执行。附件也核对扫描身份、预览后变化、完整复制 SHA-256、操作记录和安全停止。遇到问题保留已完成副本，剩余停止，不承诺整组原子成功；记录包含每项类型及未处理清单。新整组批次停止后不提供普通媒体的“核对此批次未处理项”快捷勾选，以免附件混入照片分类；请逐项核对，再选择整组重新预览。已有成功副本会触发不覆盖保护，不能直接重跑整个批次到同一目标。旧批次可能缺少类型或整组标记，需要对照附件清单人工核对。只支持整组复制，清理仍只处理明确勾选的媒体。

**复制前核对影片整组（Mac / Windows 一致）：**文件管理列表中，每个视频都有“影片整组核对”。不必选择复制目标，即可查看当前作品版本的全部视频、字幕、NFO、封面、剧照，以及当前分类计划和未明确关联原因。只读取扫描报告和已保存的分组，不访问原媒体；离线和历史快照仍能查看记录。封面 / 剧照的分类计划是独立处理建议，整组复制实际沿用本组视频目录并保留 `extrafanart/` 子目录，不另改附件计划。附件缺少不表示影片损坏，记录不证明视频目前可播放。

点击“勾选本组视频”会替换当前勾选，只选择当前版本的全部视频分段，不含其他版本或封面 / 附件；不自动纳入计划。随后可统一目录、核对纳入，再预览“影片和附件整组复制”。勾选前重新检查分组，另一窗口修改分组时保留原勾选并提示重新核对。历史快照、已有清理记录、媒体映射缺失、超过 200 个视频或操作执行中禁用本组勾选；关闭和读取失败不改变勾选。不提供整组删除、移动或原件改名。电影的用户名归属仍按完整作品（全部版本和分段）保存，目录批量调整则只影响本次勾选。

**照片和配套文件整组复制（Mac / Windows 一致）：**打开照片页或文件管理页，只勾选已核对并纳入计划的照片，选择独立目标目录，点击“预览照片和配套文件整组复制”。将同目录、同名的唯一 RAW＋JPEG 配对、匹配的 XMP / AAE 和唯一 MOV / MP4 / M4V 视频候选展开到确认页。配套文件复制到勾选照片的分类目录（包括用户名、年月目录），保留原文件名及扩展名大小写；不会另改配套媒体的分类计划。未勾选的配对媒体若仍待核对且使用扫描默认建议，可在此次预览中一起确认；若已暂缓，或已有另一已纳入 / 调整的分类位置，则拒绝展开，须先统一计划。两张配对照片同时勾选时，须纳入同一目录。使用同名后缀建议或手动改名后，请先恢复原文件名，保持配对关系。

**复制前核对照片配套文件（Mac / Windows 一致）：**照片墙和文件列表中，每张照片都有“配套文件核对”。无须选择复制目标，即可查看本次报告记录的照片 / RAW / 同名视频候选 / XMP / AAE 数量、大小、原路径、当前分类计划及未明确关联原因；缺少身份记录会提示重新扫描。与整组复制使用相同关联规则，只有扫描记录，不确认原文件目前存在或格式可解码；没有找到配套文件也不表示照片损坏。历史快照和磁盘离线时仍可查看记录。

点击“勾选本组照片”会读取最新计划并替换当前勾选，只选择唯一 RAW＋JPEG 配对的两张照片（没有明确配对时仅选择当前照片），不会勾选视频候选、XMP / AAE 或歧义照片，也不会自动纳入计划。随后可统一归属用户名、批量调整目录、核对并纳入，再通过“预览照片和配套文件整组复制”确认复制。历史快照、缺少本机媒体映射、已有清理成功记录或文件操作执行中，不能用此按钮勾选；需先重新扫描或等待操作完成。关闭核对弹窗不改变勾选，读取失败可重试；没有整组清理、移动或原件改名行为。确认启动文件操作后会清空勾选，同时退出“只看当前勾选”，便于继续查看文件和处理记录；启动失败则保留勾选与筛选。

照片配对依据只来自本次报告中的同目录文件名，不读取 Apple 内容标识或证明是 Live Photo，也不证明 RAW / JPEG 内容属于同一次拍摄。视频明确标为“配对视频候选”，需要人工核对；XMP / AAE 复制用于保留编辑资料，不保证其他软件可恢复编辑。`IMG.dng.xmp` 只匹配指定扩展名，`IMG.xmp` 可匹配唯一 RAW＋JPEG 组合；多张同名照片、多个同名视频或不明确的附件列出未加入原因。不会跨来源目录配对。普通复制仍只复制勾选媒体；整组复制才展开配套文件，并须重新勾选确认。缺少扫描身份、预览后文件变化、双平台名称冲突、目标已存在或展开超过 200 项时拒绝操作。每项复制校验完整 SHA-256，原件保留，可安全停止，记录照片 / RAW / 配对视频候选 / XMP / AAE 类型及未处理项；不保证整组原子成功，已有副本不会覆盖或自动重试。Mac 与 Windows 使用同一套关联、预览和复制代码。

**普通复制与清理只处理勾选的媒体文件。** 字幕、NFO、封面图、XMP、AAE 等未勾选文件不会随普通操作一起处理；照片或影片配套文件须通过对应整组复制核对。清理没有整组展开，也没有整文件夹移动或删除功能。保留原目录完整性时，可先在 Finder / Windows 文件资源管理器中手动管理。

执行期间保持终端和本机服务运行，控制台会阻止在文件操作进行时退出。每项操作先保存记录；遇到错误会保留已成功项并停止后续项，不会自动撤销、重试或删除已复制结果。“操作进度与记录”显示复制与副本校验的字节进度及逐项结果，持久记录在本次报告的 `operations/*.json`。Mac 与 Windows 共用分页进度界面：每批次明细每页最多 50 项，按成功、处理中、未开始、已取消和需核对筛选，路径或错误搜索覆盖整个批次。当前处理文件独立显示，不受明细筛选影响；异常可一键查看。自动刷新保留搜索内容、筛选与页码，不重新挂载同一批次的输入控件；服务中断的处理中项标为待核对，旧记录缺少清单的项目继续明确提示，不能据此判断已完成。自动分批的停止按钮明确停止整个整理任务。强行关闭终端或服务中断可能在分类目标留下 `.media-copy-` 开头的临时副本；系统返回结果不明时会提示核对原位置、目标或废纸篓，请核对记录后再手动清理临时副本，不要直接重复执行。操作后重新扫描，历史报告仍保留原快照。首次使用废纸篓功能会按需编译 `native/trash_media.swift`，缺少本机 Swift 编译器时可继续使用 Finder 手动清理。

## 报告文件

`report.html` 为中文总报告；`library.html` 为可搜索的影片海报墙；`library_issues.csv` 为影片待核对清单；`inventory.csv` 为完整清单；`duplicates.csv` 为精确重复明细；`similar.csv` 为相似图候选；`video_groups.csv` 为相关视频候选；`sidecars.csv` 为 XMP、AAE、字幕及 NFO 附属文件关联清单；`folder_names.csv` 为文件夹名称及已扫描媒体内容校验；`classification.csv` 为分类建议；`issues.csv` 为读取问题；`report.json` 保存完整结构化结果。`previews/` 和 `covers/` 存放报告所需小图，不写入原媒体目录。`reports/library-tags.json` 保存跨扫描标签，默认不上传 GitHub。

工作台的历史下拉框显示最近 50 次有效扫描，并显示文件、照片、视频、精确重复、相似候选和读取问题数量。未完成或无法读取的报告会跳过并提示；更早的报告仍保留在结果文件夹中。“单独打开”可将当前视图打开到独立页面，各报告页面提供“返回控制台”入口。整理页面由本机服务提供，不能通过双击报告文件编辑核对进度。

照片解析复用最多两个本机 ImageIO 进程，减少大量照片逐张启动程序的开销。每张照片仍有独立的读取期限；工作进程只返回部分响应、响应过长或超时会被终止，单张失败会记录问题并继续后续扫描。失败的图片预览不会在报告中留下半成品文件。

HTML 为便于浏览，最多显示 300 组重复、300 对相似图、300 组相关视频、300 项附属文件、300 组文件夹名称候选和 500 条问题；分类建议可在页面搜索全部扫描结果并按照片/视频筛选，每页显示 100 条。完整数据查看 CSV / JSON。相似候选默认最多 5,000 对，只有超过上限才提示结果不完整，可缩小扫描范围或调整上限。大清单会使本地 HTML 报告变大。

报告含文件完整路径，请保存在本地，分享前自行检查。CSV 对可能被表格软件识别为公式的文本做了转义。

## 安全与范围

默认跳过隐藏项、符号链接、应用包、Apple 照片资料库包和系统能识别的云端占位项；直接选择符号链接目录或资料库包内部目录也会拒绝。不直接扫描 Apple“照片”资料库：请先从照片应用导出原片，再选择导出目录。不同云盘的占位标记不统一，读取其他云盘的占位文件仍可能触发下载，建议扫描已下载到本地的目录。扩展名用于判断是否为媒体，不能验证视频是否可播放。

每次生成独立报告，不覆盖旧报告；解析缓存不包含用于查重的文件哈希。扫描时原媒体只读打开，图片组件拒绝符号链接输入；预览图只新建在私有报告目录，拒绝覆盖已有文件。标签编辑页面仅监听本机 `127.0.0.1` 的随机端口，并用随机地址令牌限制访问；标签只写入报告根目录。不会扫描未选择的整台电脑，也不跟踪远程 `.strm` 链接。对来源不可信的图片或视频，可用 `--no-image-metadata --no-video-covers` 跳过封面解码，仅做文件字节查重。

文件打开接口只接受本次报告中已扫描媒体的标识，不接受任意路径，要求来自同一本机页面，并拒绝任何路径层级的符号链接。新报告（JSON version 10）在操作前核对设备、文件身份、大小与纳秒修改/状态时间；较旧报告只核对大小与修改时间。系统打开用固定参数数组，不通过 shell 执行文件名。若只有状态时间变化而设备、文件身份、大小与修改时间一致，且扫描已保存完整SHA-256、文件不超过64 MiB，打开/页内预览会重新完整读取并核对内容，确认未变后恢复浏览；此次核对不会更新删除或复制的身份记录。缺少哈希、大文件、内容或其他身份变化仍需重新扫描。在主界面嵌入的媒体中心可点击“重新扫描来源目录”，扫描当前报告的原始来源并保留当前电影/视频/照片栏目；“刷新页面”仅重读报告。恢复快照不能通过该入口操作原文件。打开后由默认程序负责查看与播放；在该程序或 Finder 中自行进行的编辑、移动与删除会改变原文件。

## 命令行（可选）

在本目录打开终端：

```sh
python3 media_scan.py "/路径/照片" "/路径/视频" --open
python3 media_scan.py "/路径/视频" --video-rule name
python3 media_scan.py "/路径/视频" --video-rule folder
python3 media_scan.py "/路径/媒体" --no-image-metadata --no-similar
python3 media_scan.py "/路径/照片" --distance 4 --max-similar 10000
python3 media_scan.py "/路径/视频" --check-video-headers
python3 media_scan.py "/路径/视频" --edit-tags
python3 media_scan.py --serve-library
```

`--output` 改变报告存放位置，`--include-hidden` 包含隐藏媒体。`--no-similar` 只关闭图片比较，仍读取照片日期；`--no-image-metadata` 同时跳过照片日期解析、相似检测、视频信息读取及封面生成。`--check-video-headers` 只做轻量文件头识别，不解析视频画面、音轨或播放时长。`--edit-tags` 在扫描后启动本机标签页面，`--serve-library` 不扫描而打开最近一次报告。没有图片或视频组件时精确文件查重仍可用。`python3 media_scan.py --help` 查看所有参数。

图片和视频组件源码分别是 `native/image_probe.swift` 与 `native/video_cover.swift`，编译后的本机程序不提交到 GitHub。图形界面首次扫描时会按需自动编译；手动运行命令行扫描前也可自行编译：

```sh
swiftc native/image_probe.swift -o native/image_probe
swiftc native/video_cover.swift -o native/video_cover
```

### 预览可靠性（macOS / Windows）

照片、视频和相册封面共用可见范围补图队列；相册已有封面读取失败也会尝试补图。短暂连接失败、服务暂时不可用或解码队列忙时，最多自动重试一次，仍失败则保留原因与手动重试入口；磁盘离线会提示检查连接，不承诺正在生成。缺少可见性观察能力的浏览器会补充当前页预览。

两平台默认 Pillow 图片预览将透明背景合成为白色，避免透明区域显示为黑块；FFmpeg 视频封面遇到接近全黑的画面，会在有时长信息时尝试中段和开头，总处理时间受限。所有候选都黑时仍显示真实截帧，不伪造画面。上述质量改善适用于新生成预览，已有有效预览不会强制重做；需要更新旧预览时，可勾选“重新解析全部媒体”后重新扫描。Mac 无共用依赖时的原生降级路径仍按原生截帧行为执行。格式不支持、文件损坏或磁盘离线仍可能无法生成，原件保持不变；不在运行时联网安装组件。
