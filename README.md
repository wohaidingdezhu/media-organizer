# 媒体整理助手

离线扫描照片与视频，找出内容完全相同的文件，并提供分类建议。所有可修改源码、启动文件和说明都集中在此项目目录。**只读原文件，没有移动、重命名、删除或联网上传功能。**

## 开始使用

1. 在 Finder 打开本文件夹，双击 `开始扫描.command`。
2. 选择需要扫描的照片或视频文件夹，可以多选。首次使用建议选一个较小目录。
3. 等待扫描结束，浏览器会打开报告。报告同时保存在 `reports/scan-日期时间/`。

需要 macOS 和 Python 3.9 或更新版本。图片组件使用系统 ImageIO，不需要额外下载 Python 库；首次双击启动时会尝试用本机 `swiftc` 编译，缺少 Swift 编译器时仍可进行 SHA-256 精确查重。若启动文件不能双击，可在终端运行 `python3 media_scan.py --open`。扫描过程中按 Ctrl+C 可取消，不会改动原文件；导出阶段取消可能留下未完成报告。

## 查重方式

- **精确重复**：先按大小筛选，再完整读取候选文件计算 SHA-256；只对内容相同的非空文件分组。大小唯一的文件不必哈希，状态会写入清单。
- **硬链接**：多个路径指向同一物理文件时单独标记，不重复计入副本大小。
- **相似图片**：系统图片组件生成 64 位 dHash，默认距离不超过 6，且宽高比差异不超过 8%。纯色和低细节图跳过比较，动画只比较第一帧。报告为前 300 对候选生成本地小预览图，方便并排核对。只有发现超过候选数量上限时才标记结果不完整。结果只是人工检查候选，不能据此删除。裁剪、旋转、颜色变化、连拍可能误报或漏报。
- **视频**：支持完全相同的文件查重；另按相同编号或去掉常见分段、画质标记后的标题列出“相关视频候选”，并展示大小、文件修改时间和 SHA-256 校验状态。`-C`、`-CH` 字幕变体与 `CD2`、`DISC2`、`PART2`、`PT2` 分段仅显示为文件名标记，不证明实际有字幕或可播放。相关候选不代表内容相同；不识别重新编码、剪辑或不同分辨率的同一视频。可选用 `--check-video-headers` 读取每个受支持视频的前 32 字节，提示 MP4、MOV、M4V、3GP、MKV、WebM、AVI、FLV 的常见容器头是否可识别；这不能证明视频可播放，其他格式保持“未检查”。默认不开启，以免对云盘占位视频增加读取。

“多余副本大小”为逻辑字节估算；APFS 克隆、压缩、云盘等会让实际可释放空间不同。扫描期间文件变化或不可读会列入问题报告。结果只代表成功扫描的范围。

## 分类预览

- 照片：`照片/年/月/照片或截图或RAW或动图/原文件名`。
- 日期依次取 EXIF 拍摄时间、文件名里的有效日期、文件修改时间。修改时间不一定是拍摄日期，报告会明确标注。
- 视频默认优先识别类似 `ABC-123` 的编号，建议归入 `视频/编号/ABC-123/`。分段、字幕和画质标记保留在文件名中；同编号不等于重复。
- 无编号的视频优先保留子目录层级；扫描根目录下的视频按名称建议归组。可指定按名称或原目录整理。
- 与照片同目录同名的 MOV/MP4/M4V 提示可能是实况照片配对视频，需要人工确认；若同名照片不止一张，则保留在视频分类并标出配对不明确。XMP、AAE、字幕及 NFO 会列在附属文件清单中，只按同目录文件名寻找对应媒体；多项候选和孤立文件会明确标记。不会读取附属文件内容，也不会为它们执行移动或修改。
- 报告会列出同名文件夹，以及不同原名经过安全化后变成同一建议名称的文件夹。若两个互不包含的文件夹下所有已扫描媒体都取得完整 SHA-256，且媒体字节内容集合一致，会给出一个匹配文件夹示例；哈希不足时标记“未确认”。这只比较已扫描的媒体，不比较文件名、非媒体文件和跳过项，因此不能据此认定整个文件夹完全相同。保留原目录的视频建议遇到同名扫描根目录或同级目录名称冲突，会给目录加来源路径标识，避免不同来源混在一起。
- 重名目标文件会追加来源路径标识，避免建议里出现互相覆盖。建议不是已创建的目录，也不会自动执行。

## 报告文件

`report.html` 为中文报告；`inventory.csv` 为完整清单；`duplicates.csv` 为精确重复明细；`similar.csv` 为相似图候选；`video_groups.csv` 为相关视频候选；`sidecars.csv` 为 XMP、AAE、字幕及 NFO 附属文件关联清单；`folder_names.csv` 为文件夹名称及已扫描媒体内容校验；`classification.csv` 为分类建议；`issues.csv` 为读取问题；`report.json` 保存完整结构化结果。`previews/` 存放报告所需的相似图片小预览图，不写入原媒体目录。

照片解析复用最多两个本机 ImageIO 进程，减少大量照片逐张启动程序的开销。每张照片仍有独立的读取期限；工作进程只返回部分响应、响应过长或超时会被终止，单张失败会记录问题并继续后续扫描。失败的图片预览不会在报告中留下半成品文件。

HTML 为便于浏览，最多显示 300 组重复、300 对相似图、300 组相关视频、300 项附属文件、300 组文件夹名称候选和 500 条问题；分类建议可在页面搜索全部扫描结果并按照片/视频筛选，每页显示 100 条。完整数据查看 CSV / JSON。相似候选默认最多 5,000 对，只有超过上限才提示结果不完整，可缩小扫描范围或调整上限。大清单会使本地 HTML 报告变大。

报告含文件完整路径，请保存在本地，分享前自行检查。CSV 对可能被表格软件识别为公式的文本做了转义。

## 安全与范围

默认跳过隐藏项、符号链接、应用包、Apple 照片资料库包和系统能识别的云端占位项；直接选择符号链接目录或资料库包内部目录也会拒绝。不直接扫描 Apple“照片”资料库：请先从照片应用导出原片，再选择导出目录。不同云盘的占位标记不统一，读取其他云盘的占位文件仍可能触发下载，建议扫描已下载到本地的目录。扩展名用于判断是否为媒体，不能验证视频是否可播放。

每次生成独立报告，不覆盖旧报告，不缓存未经本轮校验的文件哈希。原媒体只读打开，图片组件拒绝符号链接输入；预览图只新建在私有报告目录，拒绝覆盖已有文件。不会扫描未选择的整台电脑，也不跟踪远程 `.strm` 链接。对来源不可信的图片，可用 `--no-image-metadata` 跳过系统图片解码，仅做文件字节查重。

## 命令行（可选）

在本目录打开终端：

```sh
python3 media_scan.py "/路径/照片" "/路径/视频" --open
python3 media_scan.py "/路径/视频" --video-rule name
python3 media_scan.py "/路径/视频" --video-rule folder
python3 media_scan.py "/路径/媒体" --no-image-metadata --no-similar
python3 media_scan.py "/路径/照片" --distance 4 --max-similar 10000
python3 media_scan.py "/路径/视频" --check-video-headers
```

`--output` 改变报告存放位置，`--include-hidden` 包含隐藏媒体。`--no-similar` 只关闭图片比较，仍读取照片日期；`--no-image-metadata` 同时跳过照片日期解析和相似检测。`--check-video-headers` 只做轻量文件头识别，不解析视频画面、音轨或播放时长。没有图片组件时精确文件查重仍可用。`python3 media_scan.py --help` 查看所有参数。

图片组件源码是 `native/image_probe.swift`，编译后的本机程序不提交到 GitHub。双击启动文件会在需要时自动编译；手动运行 Python 脚本前也可自行编译：

```sh
swiftc native/image_probe.swift -o native/image_probe
```

## 两个参考项目：借鉴的管理思路

- [JavBoss](https://github.com/Solr159/JavBoss#readme)：借鉴媒体目录与工具数据分开存放、添加目录后建立清单、文件指纹关联媒体的思路。本工具采用只读扫描和独立报告。
- [JvedioNext](https://github.com/spartawhy117/JvedioNext#readme)：借鉴规范编号与不规则本地资源分开组织、不规则资源保留目录层级、集中展示库内问题的思路。[其命名规则](https://github.com/spartawhy117/JvedioNext/blob/master/standard-library-naming-rules.md)提醒需要区分作品编号、分段和版本。

这里是自行实现的小工具，并非这两个项目的修改版，也没有安装或执行它们的代码。SHA-256 精确查重、照片年月分类和 dHash 相似候选是针对本次需求实现的能力，不意味着参考项目本身提供这些功能。编号规则只作启发式建议，不宣称完整兼容其标准库。

## 项目文件

- `media_scan.py`：扫描、查重、分类和报告生成。
- `native/image_probe.swift` / `native/image_probe`：图片解析组件源码和本机程序。
- `开始扫描.command`：Mac 双击启动入口。
- `test_media_scan.py`：使用临时样例数据的安全性与结果测试。
- `PROJECT_STATUS.md`：后续项目对话的交接记录。

`PROJECT_STATUS.md` 含本机工作记录，默认不提交到 GitHub。后续修改请集中在本目录，不要修改用户的原始媒体。

## 本地测试

```sh
python3 -m unittest -v test_media_scan.py
```

测试只生成临时样例图片和模拟视频字节，不访问个人媒体。文件头检查能排除一部分误命名文件，例如把 HEIC 图片改名为 MP4，但不能验证视频完整性或可播放性。
